THIRD PARTY LICENSES
====================

Chuying Proxy Play（褚嬴代打）内置四个开源棋类引擎。自 2.0 起，引擎不再以独立
可执行文件（子进程）方式调用，而是**编译成 JNI 原生库、在游戏进程内运行**
（前三个引擎的 stdin/stdout 被重定向到内存队列；围棋引擎直接调用其 C API，
连文本协议都不走），不 spawn 任何 OS 进程。

1) Pikafish（中国象棋引擎）
   Source:  https://github.com/official-pikafish/Pikafish
   License: GNU General Public License v3.0
   说明:    随 jar 分发的 chuying_pikafish 原生库由 Pikafish 源码 + 本 mod 的
            JNI 桥接层（native/src，同样 GPL-3.0-only）链接而成，构建期补丁见
            .github/scripts/build_native.sh（重命名 main()、屏蔽 Windows 下用进程
            命令行覆盖 argv 的行为）。
   权重:    随附的神经网络权重 pikafish.nnue 遵循 Pikafish 的 NNUE 许可 ——
            仅限个人、非商业用途；任何商业使用需向 Pikafish 团队另行获取商业授权。
            NNUE 许可全文见同目录 pikafish_NNUE_LICENSE.txt

2) Stockfish（国际象棋引擎）
   Source:  https://github.com/official-stockfish/Stockfish
   License: GNU General Public License v3.0
   说明:    随 jar 分发的 chuying_stockfish 原生库链接 Stockfish 源码；两份 NNUE
            权重（nn-1c0000000000 / nn-37f18f62d772）在构建期以 INCBIN 编入该库，
            因此不需要额外权重文件。

3) Rapfi（五子棋/连珠引擎）
   Source:  https://github.com/dhbloo/rapfi
   License: GNU General Public License v3.0
   说明:    随 jar 分发的 chuying_rapfi 原生库链接 Rapfi 源码，构建期关闭其
            MULTI_THREADING（避免在 Windows 加载期初始化全局对象时创建线程而死锁）。
   模型:    随附的 model210901.bin / mix9svqfreestyle_bsmix.bin.lz4 来自 Rapfi
            官方发布，遵循其仓库同样许可。

4) GNU Go（围棋引擎）
   Source:  https://ftp.gnu.org/gnu/gnugo/gnugo-3.8.tar.gz （GNU Go 3.8 稳定版；
            官网 https://www.gnu.org/software/gnugo/）
            tar sha256: da68d7a65f44dcf6ce6e4e630b6f6dd9897249d34425920bfdd4e07ff1866a72
   License: GNU General Public License v3.0 or later（GPL-3.0-or-later，
            源码头文件写明 "version 3 ... or (at your option) any later version"）
   说明:    随 jar 分发的 chuying_gnugo 原生库链接 GNU Go 源码（interface/CMakeLists.txt
            的 ADD_EXECUTABLE 在构建期改为 STATIC 库）。与另外三个引擎不同，围棋**不**
            走 stdin/stdout 文本协议（GNU Go 用的是 C 的 FILE* 流，Windows/MinGW 没有
            fopencookie/funopen 无法在进程内重定向），而是由桥接层直接调用其引擎 C API：
            init_gnugo() -> gnugo_clear_board() + 逐个 add_stone() 摆当前棋面与劫点 ->
            genmove()。桥接层见 native/src/gnugo_bridge.cpp。
   无权重:  GNU Go 是纯读取式引擎，不需要神经网络权重文件。
   构建期补丁（全部公开在 .github/scripts/build_native.sh，可复现）:
             a) interface/CMakeLists.txt：ADD_EXECUTABLE -> ADD_LIBRARY STATIC；
             b) patterns/CMakeLists.txt：GET_TARGET_PROPERTY(... LOCATION) 改为生成器
                表达式 $<TARGET_FILE:...>（CMake >= 3 的 CMP0026 禁止配置期读取 LOCATION）；
             c) 用 -fcommon 等开关适配现代编译器（GCC 10+/Clang 11+ 默认 -fno-common）；
             d) **三处 GNU Go 3.8 自身缺陷修复**（Linux 只是靠未初始化内存恰好为 0 侥幸
                通过，macOS/arm64 必现 abort；用 execinfo 调用栈定位到崩点）:
                  1. engine/combination.c: aa_init_moves() 只设 attacks[0].move 哨兵，
                     target[] 其余槽位是未初始化栈内存，会被 aa_sort_moves()/get_aa_value()
                     当作目标位置使用 -> 改为整数组初始化；
                  2. utils/gg_utils.c: gg_sort() 没有 nel < 2 保护，nel == 0 时
                     end = base + width * (nel - 1) 会 size_t 下溢 -> 加早退；
                  3. engine/board.c: countlib/countstones/findstones 收到非法位置时改为
                     返回 0（进程内引擎不能让 abort 连坐杀掉整个 Minecraft JVM）。

GPL 合规说明（对应源码获取方式）

上述四个引擎均为 GNU GPL（前三个 GPL-3.0，GNU Go 为 GPL-3.0-or-later），本 mod 本体
同样以 GPL-3.0-only 发布（见 jar 内 LICENSE），因此链接后整体仍为 GPL-3.0，许可兼容。

GPL 要求分发二进制时提供**对应源码**。本 mod 的做法：
  - 对应源码落点：引擎源码本体取自上游（GNU Go = 上述官方 tar，sha256 已固定），
    本 mod 的修改（JNI 桥接层 native/src/*.cpp、native/CMakeLists.txt）随本仓库公开，
    构建期所打的全部补丁见 .github/scripts/build_native.sh —— 上游源码 + 本仓库的
    桥接层与补丁脚本合起来即 GPLv3 意义上的 Corresponding Source，可从任意发布
    tag（如 2.1）完整取到（2.1 起 native/ 追踪在发布树内）；
  - 引擎源码不打进 jar（体积原因），而是在 CI 构建时从上游仓库/官方 tar 包按固定
    commit / 固定 sha256 拉取；
  - 每个发布版本的构建产物内附带 BUILD_INFO.txt，记录四个引擎的仓库地址与
    精确 commit hash / tar 包 sha256（下载页的 Release 说明中同样列出）；
  - 构建脚本 .github/scripts/build_native.sh 完整公开了源码所打的全部补丁，
    据此可复现出与本 mod 完全一致的引擎二进制。
